# 那么多国产龙虾，hermes，Claude等智能体为什么我还是建议你用codex。

![文章封面](../../covers/2026/202606072039.jpg)

> 作者：旺哥 · 公众号：AI应用实战派PRO  
> [查看微信公众号原文](https://mp.weixin.qq.com/s?__biz=MzY4NDA4MDUwMA==&mid=2247484146&idx=1&sn=caa5479ec92ed89b90004835bcf1e01f&chksm=f264dd6eb7e914a8fc494b4e4079f0337691fead80e4c324f53facbba7d13c9a130c0778b8b6#rd)

3月份的时候，国内冒出来一批“龙虾式”“爱马仕式”的 AI
助手，各个大厂都推出了各种龙虾，但是最近似乎都消失了，讨论稍微多一点就是workbuddy,其他就是qclaw这些有的，原因是啥，我这里稍微总结一下：

主要是codex和Claude太能打了！，不服评论区反驳！

话说回来，国产的各种龙虾我也尝试了不少，tokens也烧了了不少，刚开始养龙虾确实容易上头：好像往后养一个 AI
助手，它就能帮我盯消息、写东西、查资料、跑任务，一条龙全包了。

但真用过一段时间之后，我现在反倒更愿意让大多数小白先从 Codex 上手。倒不是那些 Agent 没价值，单纯是 Codex 更容易帮你把一件事做完。

01

##  国产龙虾为什么热了一阵

主要原因是开源的龙虾安装确实难倒了不少人，然后大厂看到了机会，纷纷跟进，把安装龙虾这个门槛降低了不少，好多人也是跟风装了，但用久了就发现了，真正上手很难，而且很烧tokens，最主要的是解决问题的能力并不高。所以热乎劲已过，就逐渐卸载了。

02

##  Codex 的优势不是“只会写代码”

到现在还有不少人把 Codex 当成一个编程工具，这个理解我觉得已经不太够了。我自己这段时间用它，更多是把它当一个工作台在使。

最主要是内置的生图功能太香了，比如我可以让它根据文章内容自动生成相应的图片：流程图，对比图和文章封面
。这一点Claude真的做不到。哈哈目前已经完全离不开codex了。

举几个我最近真让它干的活，大半跟写代码不沾边：把一摞零散资料理清楚、写初稿、把内容排成能直接看的页面、拆几个 GitHub
仓库看看值不值得用，链接飞书做数据中台、规划一套知识库方案、给一条 n8n
工作流写方案，做竞品拆分系统，甚至让它查网络，查代理缓慢的原因。看一下codex做的n8n：

我就简单说了一下要求，它就一条龙做出来了！

03

##  为什么它更适合非编程人员

小白用 AI，最怕的其实是这么一种局面：聊得很多但是，但是很难把这段建议变成能存下来的文档、能预览的页面、能发给同事看的表格、下次还能接着用的 SOP。

Codex 的好处：资料丢进去它能读，草稿写出来它能改，页面做好它能帮你检查，整条流程跑顺了，还能收拾成一个资料包，回头交给
Claude、OpenClaw、Hermes 或者别的 Agent 接着用。这一点对小白特别关键。

也正因为这样，Codex 现在越来越不像一个程序员专用的代码助手，倒更像一个能读文件、改文件、做页面、跑脚本、顺手把资料归置好的工作空间。

04

##  Claude Code 很强，但不是所有人都适合先上

Claude Code
当然很强。你要是手上有稳定账号，有预算，也愿意在代码项目里长期泡着，它很值得上，代码理解、复杂重构、项目讨论还有推理质量，都是它的强项。

但对不少国内用户来说，它有几个绕不开的现实问题：  账号要弄到手、还得能稳定用，本身就不一定省心；订阅也不便宜，真把它当成天天跑的工作流，额度掉得会更快
。所以我现在一般这么建议——你是开发者，或者愿意为一套高质量的代码工作流付费，Claude Code
可以直接当主力；但你要是做内容、做电商运营、做数据分析，或者就是想先把文章、图片、页面、飞书、Dify、n8n 这些事一件件先跑起来的实操党，Codex
上手会轻松不少。它不一定每个问题都答得比别人漂亮，可它更像一个能把事真正落到本地的工作台。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/H159gTor6F6QAZF4iciblAo0YGZ39PicXgp2sl8gcZib9C4VL4iaeYGUFFIajnYbeG3ZtKGoCmbUuTDq6muLHojgrzAQ75IQ8xtDMePnyPuicB84c/640?wx_fmt=png&from=appmsg)

05

##  Codex 真正特殊的地方

我自己觉得，Codex
最近越来越火，核心不在某一个功能上，而是它把好几样能力凑到了一块儿。它能读项目里的文件，省得你每次重新复制一遍资料；它能直接改文件，文章、页面、脚本、表格说明、资料包都能落到目录里；也会调脚本、查文件、把结果生成出来。再往后
飞书、Dify、GitHub、n8n、浏览器控制、图片生成  这些一旦接上，它就能在中间帮你居中调度。

![](https://mmbiz.qpic.cn/mmbiz_png/H159gTor6F7zJQ75iah3zhyR0sqgguXvECrjAXTRibo3iaoYdsAmVFrkyPhDk0mswWpaPwoBAGdVUKyrXAPFXKeyLo54tXuVwSq2LNzdia9hY8k/640?wx_fmt=png&from=appmsg)

就拿这次来说，我顺手补了一条 n8n 工作流，

![](https://mmbiz.qpic.cn/mmbiz_png/H159gTor6F4N8OxGBzkNXQkPYIvb1acgNHG8kJ6jdL6Bom37RIibeztlAwhP9ndEFuTNRFdF6GWuiaPguIKVNmUPCnJZvf6mUymIjBDibd8jvY/640?wx_fmt=png&from=appmsg)

在这条流程里，Codex 不是来替代 n8n

06

##  那龙虾和爱马仕还要不要用？

那国产那些龙虾、爱马仕，是不是就不用看了？倒也不是，得看你想解决的是什么。你要的若是一个线上的个人助理，能接消息、能接定时任务、能在好几个 Agent
之间分发活儿，那hermes很不错。但你要是文章怎么收尾、页面怎么排好、飞书表格怎么理清、GitHub 仓库怎么拆、Dify 知识库怎么测、n8n
工作流怎么先跑起来这种很具体的事，那我会先让你试 Codex。

07

##  我现在的选择建议

我现在的建议大概是这样。只想聊聊天、碰碰想法，ChatGPT 或者 Claude 都够用；要认真写代码，账号和预算又都稳，Claude Code
很能打；想养一个长期 AI 助理，龙虾、爱马仕这类可以接着研究。但你想要一个真正干活的  agent  ，我现在还是更愿意推荐 Codex。它不乱封号呀！

Agent 之间这场竞争，比的已经不只是模型答得好不好，而是谁更能接住你手里那摊真实的活。
