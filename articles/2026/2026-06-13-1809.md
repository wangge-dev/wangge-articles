01

##  先安装和登录

第一次用 Codex，先不要研究插件，也不要先研究 MCP。

第一件事就是把入口跑通。

新手最适合从 Codex App 开始，也就是桌面端。原因很简单：它能看到项目、对话、文件变化、预览、插件入口，对普通人更直观。

如果你已经熟悉终端或编辑器，以后可以再用 CLI 或 IDE 扩展。但第一次上手，建议先把桌面端跑起来。

系统  推荐方式  macOS  直接下载安装 Codex App  Windows  优先从官方入口或 Microsoft Store 安装
已熟悉命令行  再考虑 CLI

登录方式也先按简单路线来。

Codex 常见有两种登录方式：ChatGPT 账号登录，或者 API Key。

下载地址：  https://chatgpt.com/zh-Hans-CN/codex/

如果你已经有 ChatGPT 账号，先用 ChatGPT 登录。它最接近普通软件的使用体验，不需要一开始就理解 Key、Base URL、环境变量这些东西。

如果你后面要接自动化、脚本或其他模型，再研究 API Key。如果用 api 那我推荐你用 Codex ++这个工具就行。

##  认识两个入口：对话和项目

登录之后，先看懂两个东西：对话和项目。

对话

更像临时聊天。解释概念、整理一段话、给一个计划，都可以放这里。

项目

真正干活的地方。通常对应电脑上的一个文件夹，结果也保存在这里。

##  先把权限搞明白

Codex 和普通聊天工具最大的区别，是它可以操作文件和命令。

如果你不想频繁被索要权限就选完全访问权限！

04

##  写一份 AGENTS.md，让 Codex 记住你的规矩

安装和项目都弄好之后，下一步不是马上干活。先写一份  ` AGENTS.md  ` 。

它可以理解成“写给 Codex 看的工作规矩”。比如默认说中文、先给计划、不要乱删文件、改完要告诉你改了哪里，都可以写进去。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/H159gTor6F6PzmwRG2FQfuevEia8pkEhZl5GTgj7b3W4vvPCVyElibe7jfiaacbrIQF1UHVHx7WUkF5ncibhpsqQauhDPxAC2QFsKJnpwFzlZug/640?wx_fmt=png&from=appmsg)

# AGENTS.md  ## 工作目标 这个项目主要用于： - 资料整理 - 页面预览 - 公众号文章 - 电商图片提示词  每次任务都要尽量产出可保存的文件，而不是只停留在聊天回答里。  ## 工作规范 - 先理解资料，再开始执行。 - 修改文件前先说明计划。 - 每次只处理一个明确任务。 - 保留原始资料，不覆盖重要文件。 - 不确定的信息要标注“待确认”。  ## 验收方式 - 文件是否保存到正确目录 - 结构是否清楚 - 是否有截图、预览或检查结果 - 是否说明新增和修改了哪些文件  ## 禁止事项 - 不要删除用户已有资料。 - 不要虚构数据、来源、销量、评价。 - 不要提交账号、Cookie、Token、密钥。 - 不要把临时草稿当最终稿。

如果你只想先填两块，就填“工作目标”和“禁止事项”。这两块最能减少 Codex 乱猜。

05

##  第一个任务怎么选

现在才进入第一个任务。第一次不要选太大的目标，不要上来就做完整系统，也不要让 Codex 一次处理一堆材料。

任务  为什么适合新手  文章卡片页  结果能截图，适合公众号展示  资料整理报告  能看到 Markdown 文件，容易检查  电商图提示词表
不依赖复杂环境，适合内容和电商场景

图位 5｜第一个任务流程图

提示词  →  计划  →  HTML  →  截图  →  修复  →  记录

请你帮我完成一次 Codex 新手练习。  目标： 在当前项目里做一个可以截图的小成果。  任务类型： 做一个“文章资料卡片页”，用于展示一篇文章的标题、核心观点、适合人群、下一步行动。  要求： 1. 先给计划，不要立刻改文件 2. 生成一个可以直接打开的 HTML 页面 3. 页面要适合公众号截图 4. 同时输出一份 Markdown 实测记录 5. 说明新增了哪些文件 6. 如果页面有移动端问题，要修复后再截图

06

##  验收：不要只看它说完成了

Codex 说“完成了”，不代表真的完成。新手一定要学会验收。

看文件

新增了哪些文件？是不是放在指定位置？

看结果

页面能不能打开？移动端有没有裁切？

看记录

有没有写清提示词、计划、变化和问题？

07

##  再往后，开始创建自己的 Skill

当你能跑通第一个小任务后，就可以看 Skill 了。Skill 就是一套可复用流程。

图位 7｜Skill 创建流程图

选重复任务  →  写触发场景  →  写步骤  →  写边界  →  测试复用

比如你经常写公众号文章、电商图片、GitHub 仓库短拆解、竞品资料整理、HTML 报告排版，都可以做成 Skill。

请帮我创建一个“公众号文章整理 Skill”。  触发场景： 当我提供文章素材、截图、链接、Markdown 或实测记录时启用。  工作流程： 1. 判断素材够不够 2. 提炼主题和读者痛点 3. 设计文章结构 4. 去掉内部沟通和后台话术 5. 输出公众号初稿 6. 给出配图和截图清单  边界： 不要虚构数据。 不要暴露内部工作过程。 不确定的信息标注待确认。 语言简单，少用行话。

##  新手最容易卡住的地方

1\. 装好了不知道从哪里开始：先建一个练习项目。

2\. 项目目录选错：先让 Codex 列目录。

3\. 权限不清楚：第一次只读和分析。

4\. 任务太大：先做文章卡片、资料报告、提示词表。

5\. 没有验收：至少看文件、看截图、看记录。

6\. Skill 写得太空：写清触发场景、步骤和边界。

7\. 生图只写一句提示词：先拆图位和验收标准。

##  结尾

这篇不是想把 Codex 的所有功能一次讲完。

新手第一天不需要掌握所有按钮。先完成这一条线就够了：安装登录，建一个项目，写一份规则，跑一个小任务，检查结果，再把重复流程做成 Skill。

跑通这条线之后，你再去看插件、MCP、生图、自动化，就不会那么乱。如果你想进阶一下去看下我之前的文章，里面有很多教程和干货！
